# Audit de FarfaLauncher (23/11/2026, v1.2.1)

Audit en lecture seule, phase 1 du chantier « stabilité, documentation, autonomie ».
Le NAS, RomM, FarfaRomManager et `outils/surveille-rapports` sont dans
`FarfaRomManager/docs/audit-2026-11.md`.

État au moment de l'audit : `tsc` sans erreur, `cargo test --lib` = 203 réussis,
24 ignorés (e2e qui demandent un vrai serveur). Pas de test de l'interface.

## 1. Comment le launcher fonctionne

| Étape | Code | Ce qui se passe |
|---|---|---|
| Connexion | `commands/session.rs` | Heartbeat RomM, puis code appareil, code d'appairage ou token collé. Token rangé dans le trousseau du système (`secrets.rs`). |
| Bibliothèque | `commands/library.rs:80` `start_refresh` | `assets.json`, catalogue du gestionnaire (`manager.rs`), puis plateformes et ROM RomM. |
| Téléchargement | `install/download.rs` | Depuis RomM (`api/roms/{id}/files/content/…`) ou le gestionnaire (`files/{sha1}`), reprise et contrôle SHA-1/MD5. |
| Installation | `install/` (recomp, émulateur), `pc/` (jeux « Ordinateur », Proton sous Linux) | Extraction, `preparer:`, registre `installed.json`. |
| Lancement | `commands/launch.rs:66` → `play.rs` → `launch/` | Sauvegarde, langue, manettes, liens, shaders, puis suivi du processus. |
| Après la partie | `save_sync.rs`, `stats.rs` | Envoi de la sauvegarde et du temps de jeu ; file locale si hors ligne. |

Le token RomM sert aussi d'identifiant auprès du gestionnaire (`manager.<domaine>`) et
du serveur d'assets (`assets.<domaine>`).

**Mises à jour** (`commands/update.rs`) : canal stable (`releases/latest`), bêta
(`canal-beta`), test d'un rapport (`test-<rapport>-<n>`). Signées avec minisign, clé publique
dans `tauri.conf.json`. Vérifiées au démarrage puis toutes les 30 min.

**Hors ligne** : seul le heartbeat RomM est surveillé (`offline.ts`). Les jeux installés
restent jouables, sauvegardes et temps de jeu passent en file. Installer une recomp ou un
émulateur échoue si le gestionnaire est injoignable.

## 4. Écarts à la règle « rien dans AppData »

- Préfixes Proton et GE-Proton/umu dans le dossier de configuration (`pc/proton.rs:63-68`).
- Plutonium dans `%LOCALAPPDATA%\Plutonium` (`cod.rs:311`), clients CoD dans
  `%LOCALAPPDATA%\CallofDuty4MW` (`cod.rs:131`).
- Installé avec NSIS `currentUser`, le dossier de l'exe est `%LOCALAPPDATA%\FarfaLauncher` :
  les jeux y vont par défaut (`install/mod.rs:767-799`).

## 6. Parité Windows / Linux

Ce qui n'existe ou ne marche bien que sous Windows : réponses automatiques aux fenêtres
(`dialogs.rs`), menu en jeu au premier plan (`ingame.rs`), détection de fenêtre pour les
plantages, e2e d'émulateurs (`#[cfg(windows)]`). Le Deck stocke son token en clair
(`~/.config/farfalauncherdeck/token`, 0600). `test.yml` ne compile pas pour Mac.
